# 安装五款竖屏工作流

GitHub 中提供的是剪辑工作流和已审核的镜头编排。五款 MotionGit 个人模板须由使用者用自己的账号领取；个人 `.motion`、口播、声音和渲染缓存只保存在本机。无需复制他人的账号、Key、个人包或浏览器登录状态。

## 1. 准备本机环境

已实际验证 Windows、Python 3.12、Node.js 24、FFmpeg/ffprobe 9。工作流包装代码使用 Python 标准库，无需先运行 `pip install -r requirements.txt`。作者模板需要的 Python/Node 库和浏览器由验签后的官方 `setup` 准备。

先安装并将以下工具加入当前终端的 PATH：

| 工具 | 要求 | 官方入口 |
| --- | --- | --- |
| Python | 3.12 或更高；Windows 安装时启用 PATH | [Python 下载](https://www.python.org/downloads/) |
| Node.js 与 npm | Node.js 22.12 或更高，标准安装含 npm | [Node.js 下载](https://nodejs.org/en/download) |
| FFmpeg 与 ffprobe | 同一发行包；FFmpeg 须含 `libx264` | [FFmpeg 下载与 Windows 构建入口](https://ffmpeg.org/download.html) |

安装后重新打开终端，运行 `python --version`、`node --version`、`npm --version`、`ffmpeg -version`、`ffprobe -version`。Windows 的 `python` 若跳转应用商店，说明当前命令指向占位程序；改用已安装 Python 的完整路径或 `py -3.12`。

建议工作目录和缓存使用 E 盘短路径，有 E 盘时可选 `E:\MotionGitWork`、`E:\MotionGitCache`。不要在 GitHub 仓库或技能安装目录内保存个人包和口播。

## 2. 从 GitHub 下载并安装技能

下载整个仓库 ZIP 并解压，或在 PowerShell 中执行：

```powershell
git clone https://github.com/fagezhuanshu-lang/tech-console-video-workflow.git
cd tech-console-video-workflow
python portrait-five/scripts/install.py
```

安装器使用当前电脑的 `$CODEX_HOME/skills`，未设置该变量时使用 `~/.codex/skills`。自定义技能目录的用户可通过 `--dest` 指定实际路径。

只安装一款可以加 `--style paper`；重复该参数可选多款：

```powershell
python portrait-five/scripts/install.py --style modern --style paper --dest E:\AIApps\Data\CodexHome\skills
```

安装器会给每款生成独立目录 `motiongit-modern`、`motiongit-paper`、`motiongit-dark`、`motiongit-character`、`motiongit-poster`，各自包含 `SKILL.md` 与完整共享脚本。任一目标目录已存在就停止，不覆盖既有技能；新的五目录会先备齐文件，再提交安装。命令成功后打印实际路径，下一轮聊天即可使用。

不要只复制 `skills/motiongit-paper/SKILL.md`，也不要用只下载这个子目录的安装方式：它需要安装器一起复制 `scripts/`、`examples/` 等文件。其他能运行本地命令的助手也可直接使用完整仓库中的 `portrait-five/scripts/render.py`。

## 4. 环境检查与准备

以下命令在仓库的 `portrait-five` 目录运行；已安装技能时，在该技能目录运行同样命令。

```powershell
python scripts/bootstrap.py doctor
python scripts/bootstrap.py setup --style paper --template E:\MotionGitPackages\paper.motion --work E:\MotionGitWork\paper-setup-01 --cache E:\MotionGitCache
```

第一条只查宿主工具，不联网、不声称模板渲染能力已通过。第二条先核对随包工具的官网元数据与 SHA-256，再验签本人模板，调用本款官方组件流程的 `setup` 和 `doctor`。海报版未声明独立 `doctor`，因此直接检查其 `setup` 返回的 `dependenciesReady: true`。`--work` 每次使用新的私有目录；`--cache` 可以复用。`setup` 会下载作者声明的渲染依赖，不会替你购买模板、消费生成积分或修改系统级环境变量，既有浏览器及 LOCALAPPDATA 路径也会保留。

只诊断模板、不安装依赖，可使用新的工作目录运行：

```powershell
python scripts/bootstrap.py doctor --style paper --template E:\MotionGitPackages\paper.motion --work E:\MotionGitWork\paper-doctor-01 --cache E:\MotionGitCache
```

工具不在 PATH 时，三个命令均支持 `--node`、`--ffmpeg`、`--ffprobe` 完整路径。输出 JSON 中 `host_ready` 与 `template_ready` 分开记录。没有传个人包时，`template_ready: null` 表示只查宿主；海报的 `doctor --template` 会验签个人包，但依赖仍记为 `null`，需要通过 `setup` 确认，不把未声明的诊断命令冒充成功。

## 5. 使用自己的口播导出

如果真人口播和声音在同一个 MP4 里，可直接用它作 `--video`，再从同一片段提取原声供 `--voice` 使用。以下命令保留完整录音，并要求写入一个新文件。

```sh
ffmpeg -n -i "口播.mp4" -map 0:a:0 -vn -c:a pcm_s16le "原声.wav"
```

先让助手读完整文稿，校对字幕时码并编写本期时间线。`--init-timeline` 只生成示范结构，里面的例句必须换成本期真实内容。已有示范时间线不代表自动转写，也不能把任意口播机械改写为问答或对比。

```powershell
python scripts/render.py --help
python scripts/render.py --style paper --template E:\MotionGitPackages\paper.motion --video E:\MyVideo\presenter.mp4 --voice E:\MyVideo\voice.wav --timeline E:\MyVideo\paper-timeline.json --out E:\MotionGitWork\paper-video-01 --cache E:\MotionGitCache
```

音画输入和时间线均从本机文件读取。每次导出使用新的 `--out`，保留旧成片。完成后读取核验报告，检查实际画面的字幕、人物裁切、转场以及完整原声。首次环境检查通过不等于最终成片已经通过。

这套工作流复现的是已审核的组件样片：前四款为作者随包的 `motion-kit`，活力海报为 `poster-kit`。不把完整个人包下载成功或组件渲染通过，表述成作者全部原生编舞已经跑通。源码、模板数量与未验证范围见各技能说明。

## 故障定位和验证边界

| 情况 | 处理 |
| --- | --- |
| `Missing executable` / `host_ready: false` | 安装缺少工具或传完整路径；不要把 WindowsApps 的 Python 占位程序当作安装成功。 |
| `WinError 206` / 路径过长 | 使用较短 E 盘 `--work`、`--cache`。官方工具的新依赖和临时文件落在当前进程选择的缓存里。 |
| 官网元数据不可达 | 保留代理设置和已有个人包，恢复网络后重试。不要跳过工具哈希或签名核验。 |
| 签名、版本、模板身份不匹配 | 从表中本人领取入口获取对应版本；保留旧包，不修改签名、保护内容或账号权限。 |
| 官方 `setup` / `doctor` 报错 | 查看本次私有工作目录的 `private-logs/`；记录实际失败步骤。不要上传含个人身份的完整日志到公开仓库。 |
| 已存在的技能或输出目录 | 安装器和渲染器会停止。选择新目录，或由使用者先备份确认过的旧版本。 |

脚本使用 Python 标准库和跨平台命令参数，但这次成片复验只覆盖 Windows。macOS/Linux 可按相同流程使用 `python3` 和本机工具路径，字体、浏览器、编码结果及作者依赖仍须在该平台实际检查；未承诺其他平台已跑通或逐字节相同。
